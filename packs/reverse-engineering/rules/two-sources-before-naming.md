# Two independent sources before anything is named

A value read from a routine looks exactly as confident as a guess. Read what consumes it before naming it: a portamento table was once read as an LFO.

<constraints>
Always do:
- Write nothing into the model until two independent sources agree. A wrong name corrupts every patch and is worse than a blank.
- Count as one source: agreement on a class, a matching count, or a value fed into a table.
- Run a law over the whole corpus, in both directions, before writing or removing a name. One bank proves nothing.
- Say how sources arbitrate: firmware wins on mechanism, the manual on stated absolutes, the corpus decides between them. Keep a real contradiction; never average it.
- Treat a sibling machine's law or layout as a hypothesis. A shared name is not a shared layout. A sibling gives structure, never enum values: read every enum from your own ROM. Offsets, names and ranges agreed on 56 of 58 parameters while three of five values of one enum meant something else, and a range check, a round trip and the corpus all passed.
- Read a test that already pins a law before correcting the law. A green test that contradicts you is evidence, and it counts as a source.
- Check scope and the vendor's printing convention before logging a contradiction: a panel against the union of three ranges, or a manual that prints every score an octave high, is no contradiction.
- Count a translation as one source. Read the original language first, and break the tie with a third document.
- Rank a trimmer target agreeing with a firmware constant as the strongest pair: neither could have been fitted to the other.
- Write the firmware reading down first and let published sources confirm it afterwards: only that order makes the agreement worth something.
- Let order and arithmetic arbitrate between two printed labels: a ladder that must strictly decrease picks the right one.
- Count an exact closure the layout was not tuned to as an independent proof; a count the guess was tuned to stays one source. The rule is `layout-closes-on-itself`.
- Name a peripheral or a CPU from its own manual, never from what it seems to do.
- Check a counted field a datasheet states against another machine on the same chip before taking it.
- Treat a cited table address as a claim: open it and read its first records and ranges before reusing it (a cited table's first sixteen records were the name's ASCII).
- Test a name table identical across builds against each build's own records: the per-record field is the authority.
- Test each attribution, and the order of an enum printed in a manual, against what the preset names and the algorithm each id appears on say, and count that as a check (the one preset named MIDICLK DELAY sat alone on the third value).
- Count as an independent proof a law whose value at its maximum input lands just inside the word, lane or buffer it feeds, when the law was not tuned to that fit; one that overflows it, or leaves the lane half empty, is wrong.
- Count as an independent source each knob's pointer angle fitted in the patch book's drawn panel facsimile, correlated against the decoded columns, only for assignments the fit was not made from; a correlation fitted to the decoded data is one source.
- Before a table, name list or bank is written into a unit, read the unit's own laws file for it and check each name against the image.

Never do:
- Trust a published spec, an editor export or a datasheet alone: each has been wrong for a build.
- Change an attribution without running every source again.
</constraints>
