# Two independent sources before anything is named

A value read from a routine looks exactly as confident as a guess. Read what consumes it before naming it: a portamento table was once read as an LFO.

<constraints>
Always do:
- Write nothing into the model until two independent sources agree. A wrong name corrupts every patch and is worse than a blank.
- Count as one source: agreement on a class, a matching count, or a value fed into a table.
- Run a law over the whole corpus, in both directions, before writing or removing a name. One bank proves nothing.
- Say how sources arbitrate: firmware wins on mechanism, the manual on stated absolutes, the corpus decides between them. Keep a real contradiction; never average it.
- Treat a sibling machine's law or layout as a hypothesis. A shared name is not a shared layout.
- Name a peripheral or a CPU from its own manual, never from what it seems to do.

Never do:
- Trust a published spec, an editor export or a datasheet alone: each has been wrong for a build.
- Change an attribution without running every source again.
</constraints>
