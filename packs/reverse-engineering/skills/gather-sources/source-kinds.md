# Sources beyond the manuals

Read by `gather-sources` before a source is called missing. Each kind is a place a source hides; none is a law until two sources agree (`two-sources-before-naming`).

- **The vendor's updater and installer.** Open it before calling a firmware hidden: one `.MID` OS file passed entropy, zlib, LZO and XOR tests and was a dead end, while the Windows updater carried the OS as a plain PE resource. Its XML state machine, device ids and change log split the files by job before any byte is decoded. Other routes: a sysex update (unpack 7-in-8 before comparing), floppy images with a manifest (read one with `read-a-floppy-image`), a sibling's flash.
- **Where the factory sounds live.** A bulk dump off an untouched unit is the owner's saved patches, not the factory's (run Preset Load, then dump). A file signed by a third party is a corpus, not the factory bank. The factory sounds may be ROM presets (scan the ROM for the record stride before believing "no factory bank"), a tape-load WAV, floppy images, an editor format, or a printed patch book or chart. A printed book is a corpus: its count and its names constrain the decode, and its program numbers come from the unit's own manual. Example settings in advertising copy are not a bank. A factory-reset key combination, or an update path that replaces the presets, is evidence the presets sit in the image: look there before asking for a dump.
- **What the machine boots from.** On a sampler or any computer-like machine ask where the disks are before the ROM: the OS boots from floppy, is many times the size of the EPROMs, and prints its own parameter pages. Read those strings before opening a disassembler.
- **Host-side editor templates and librarian files.** A mislabelled "firmware updates" folder held sequencer and editor templates: a free parameter map, including controllers not on the CC table, and captions as nibble-swapped ASCII. Look wherever the maker published sequencer support.
- **Patents, and the designer.** When the algorithm is in silicon, patents are public and must teach: expect the architecture, not the tap numbers, and never tag a tap set `[PUB]` that the patent does not give. A designer's later products and manuals (a Eurorack module) can document the earlier machine. A service manual that defers to a brother model ("repeated on the service notes of those models") sends you to that sibling's.
- **A headline spec** may be the supplier's datasheet line (a filter's "30 kHz" was the chip's first line): look for the part, not the drawing.
- **Panel artwork and display photos.** Beat groupings printed under the step keys, transfer-function polynomials above the buttons, and a photograph of a lit display (`REV TIME= 2.6s` against a stored 26) are evidence for the decode.
- **Where manuals are.** The maker's own library (Roland's `static.roland.com/assets/media/pdf/MODEL_OM.pdf`, Yamaha's manual library, Korg's CDN), an index such as synthfool, the Internet Archive search, and the Wayback Machine's `id_` raw files for a page that has gone. Service manuals: synthxl.com, synfo.nl, manuals.fdiskc.com, archive.org. Skip hosts gated by script (manualslib, manualzz, scribd) as downloads: read their listing for the title and date, then fetch the file from the maker or an archive. Some hosts need a `wget` user agent, and sysexdb, mega, mediafire and Drive cannot be fetched. Record every dead source, gated site and rate limit as a gap, and say which gap it causes.
- **Converted audio beside native files.** Where converted audio ships beside native files, search each converted file's samples back into its native file; one offset across all pairs fixes the header size, the sample layout and a header byte.
