# An unattended run takes the recommended choice and records it

Where a brief says the user is away, nobody is there to ask. The rule to stop and report, and the rule to ask before a new folder, are for when someone is there.

<constraints>
Always do:
- Keep every law: an unattended run takes the recommended choice, never a way around a hook.
- Write each choice, and why, in the project's decisions file as it is made, so the user can overturn it.
- Report a hook that blocks correct work as you would with someone there: log it, mark the refusal, and fix it where the fix belongs.
- Stop only for what cannot be undone or leaves the project: publishing, deleting what you did not make, spending money, writing to another repo.
- End the run with a hand-over list for the person: what should now behave differently, each judge-by-hand item with the single constant it turns on, what is known imperfect, and which large rewrites are left for a session with them.

Never do:
- Wait for an answer that cannot come, or end a run with work left that you could have done.
- Take a brief's silence as permission to skip a gate.
</constraints>
