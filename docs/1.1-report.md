# 1.1.0 report

39 of the 41 faults are fixed, each with a test seen red first. KF-22 and KF-30 are `dspblocks` faults, left as the work order says. 1.1.0 is on `main` and is not published: publishing is the user's decision.

**One thing to decide before publishing.** After `update`, `doctor` goes red on any project whose live rules name tests it has not written. That is what KF-31 asks for, and `update` itself still passes, with a note. But the changelog's own promise is that a change that can break an installed project is a major version, and a red `doctor` may count as one. Decide whether this ships as 1.1.0 or 2.0.0.

## Hook by hook

- **`run-hooks`:** a crash on a tool call refuses once and says so; the same call again goes through, logged. At Stop or a prompt the author is told. It says when no hook could read what an inline program wrote to source.
- **`shape-law`:** reads prose as prose, by narrow tests in `lib/shape-prose.mjs`; a count is told from an index by its declared parameter.
- **`making-check`:** matches a concept whole, accepts the shape word, judges only writes after a landing, and skips the detector for tool writes `once-only` already judged.
- **`code-shape`:** every line at once; Python braces; a statement's line is its first word's.
- **`git-guard`:** judges the subcommand, not a word in an argument; reads a dry run and `--theirs` in a merge; `lib/git-auth.mjs` holds the push and `gh` laws. Its selftest moved to its lib file, taking it from 295 lines to 202.
- **`stage-guard`:** reads a dry run.
- **`suite-once`:** sees a wrapper, with options, in the background, and through `buildq`.
- **`param-id-lock`:** starts its lock at the first id, skips build output, reports a bad pattern by name, and has `--status` for `doctor`.
- **`once-only`:** leaves `using` lines, includes and one-line constants out.
- **`dispatch-once`:** tells two kinds by their cases, and refuses two switches on one kind in one new file.
- **`build-guard`:** names the queue the kit now ships.
- **`protect-vendor`:** names `buildOutput`.
- **Lesson checks:** `position-not-integrated` leaves tests alone; `cpp-find-with-the-library` needs a `return` or `break`.

## What was left, and why

- **A `.py` hook has no refuse-once net.** `browser-guard.py` runs outside `run-hooks`, so its crash still only reaches `doctor`.
- **`doctor`'s rule-test check reads text.** It proves a test names the rule, never that the test does what the Check says. It catches the silent gap, not a weak test.
- **`making-check`'s remaining time is parsing the transcript,** about 280 of the 353 ms. It is under the line, but it grows with a long session.
- **The new rule and the look laws are text.** No hook can tell a gate that writes the parameter from one that drives the input. The rule's Check names a test, so `doctor` asks for it.
- **The panel report's open questions on shading,** and what to do when "what looks grouped" and the evidence collide, have no law: no measurement here supports one.
- **Outside this work order:** why `cpp-clamp-before-cast` differs between write time and `scan`, a lesson check for a gain with no smoother (B-022), and the 32 of 45 skills never opened.
