# planner: decisions

Each choice the run made, so the user can overturn it. The first five were taken in `workorder.md` before the run.

- **d-1** Templates are chosen by `--template`, never by configuration. Options: infer from the configuration; a flag. Chosen: the flag, because a rebuild and a new synth share `synth-creator`.
- **d-2** No `start-from-a-workorder` skill in the planner: the start is `Run docs/workorders/<name>/PROMPT.md`. Options: name the skill in the planner; name the sentence. Chosen: the sentence. Note from the run: base has carried a `start-from-a-workorder` skill since 1.5.0 (written before this order ran). The planner never names it; it stays in base, since removing an installed skill is a change to every project and this order does not name it (easiest to reverse).
- **d-3** No generated index of what every skill proves: `workorder check` is the structural check instead.
- **d-4** The UI is never prototyped in HTML; both synth templates say so in their Never list, with the reason from the research.
- **d-5** `planner/` lives in this repo, not its own, so nothing is copied or pinned.
- **d-6** The release is 1.6.0, not the 1.5.0 `workorder.md` names. research-gaps published 1.5.0 first (npm shows 1.5.0). Given in PROMPT.md.
- **d-7** W0.1: doctor --strict was red on the branch because the kit's own install carried the pre-KWB-130 `agents-held`, whose selftest fails under an unattended run. Options: hand-edit `.claude/hooks`; run the kit's own `update` from this checkout. Chosen: `node bin/claude-packs.mjs update`, the kit's sanctioned path (a fix comes with update); it also brought `lib/audience.mjs`, the brief-guard and shape-law changes and `"chart": []` from 1.5.0.
- **d-8** Evidence lives in `docs/workorders/planner/evidence/W<n>/`, not `build/evidence/` (the public repo leaves `build/evidence/` out). Given in PROMPT.md. Home paths in evidence are masked as `~`.
- **d-9** W2: `workorder <name>` runs the check at its end without doctor, and returns 0. Options: the full check (doctor included) and a failing exit; the order's own lines only. Chosen: the order's lines only, printed as what is left to fill in, because a just-written order is all placeholders and the project may be mid set-up; `workorder check <name>` alone runs doctor too, and the runner calls that.
- **d-10** W2: the runner (`run.sh`) and the prompt call the check before the first session only (no `progress.md` yet). Options: before every session; before the first. Chosen: the first, since a run's own work can turn doctor red for a while (a new rule matching no file yet), and a started run is not stopped by it. `run.sh` exits 5 on a refusal. The command is written as the project runs the kit (`{{kit}}`, filled by `kitCommand`), since `npx --no-install` fails in a project with no node_modules (KWB-76).
- **d-11** W2: a placeholder is `<...>` anywhere outside a code fence, inline code included, and a Done when must hold a digit or a path to a test, as the order states. The rebuild template, kept as its source wrote it (W1.2: two changes only), has 16 of its 19 Done whens refused until filled with counts ("every sheet has its report" names no number). Recorded, not loosened: the house law is a number or a test on every step, and the planner's Stage 8 asks for the same.
- **d-12** W2 findings on `admiral-fleet` (from the history repo; the public repo left it out), checked as written for the kit itself: 13 refusals, recorded as findings about that order and not fixed (it is finished and not in this repo). 7 placeholders are metavariables in inline commands (`<main checkout>`, `<trunk>`, `<scratch>`, `<version>`, `<step>`): a finished order should name them as shell variables or fill them. 6 Done whens hold no digit and no test path (W0.0, W1, W2, W3, W7, W8), several measured in words ("one name removed", "every section has counts"). It has no install block (a warning). Evidence: docs/workorders/planner/evidence/W2/admiral-fleet-check.txt.
- **d-13** W3: the install block is parsed with `yaml` 2.9.1, pinned as the kit's one runtime dependency (row in docs/versions.md). Options: a parser of our own for the subset; a pinned parser. Chosen: the pinned one, as the order allows, because the block holds lists and maps (`looks`, `guards`) and a hand parser would be a second YAML; `yaml` has no dependencies of its own. Only `lib/` (the CLI) imports it; no hook does.
- **d-14** W3: the block's layout keys replace the layout's own values for those keys (the block is the truth for the order), then `update` runs once; `new --config X --from` with a block naming another configuration is refused, naming both; a block with no packs takes its configuration's defaults, as `init --config` does.
- **d-15** W3: the test of `enable` switches on `hooks/user-asks.mjs`, not the handover's example `hooks/idle-wake.mjs`, which crashes when enabled alone (KWB-135, logged open). KWB-136 (every update wrote `"chart": []`, breaking chart-first) was found by the noop test on this branch and fixed here, since the release ships it.
- **d-16** W4: the ledger's budget (the full polyphony in 25 % of one core at 44.1 kHz / 128, worst block) and `cpu-worst-case-per-block`'s gate (p99.9 under 50 % of the block deadline, zero overruns) measure different things. Kept both, said once in `cost-ledger.md`: the gate is the rule's, and 25 % is the planning margin that leaves it room on the reference machine. The skill states the budget as the rule's law in units, as the order says.
- **d-17** W5: `prove-a-bank` (sound-design) reads WAVs with audio-core's `tools/lib/wav.mjs`, extended to return every channel (channel 0 stays `samples`, so `tone-report` is unchanged, checked), and transforms with audio-core's FFT (`spectrum.mjs` now exports `fft`); its own measures are `tools/lib/bank-measures.mjs`. Options: a second WAV reader in sound-design (a copy `once-only` refuses); a reader in base (a synth tool in base). Chosen: reuse audio-core's, installed beside it in every synth project (synth-creator's defaults include audio-core). A project with sound-design and no audio-core cannot run it; it says so by failing to import.
- **d-18** W5: `references/tables.md` 4.5 is a generic "source kinds to kinds" table. The review names one but holds none as a table; it was made from the document's 4.5 rows with each engine generalised to its source kind (the same names the skill's vocabulary uses), and from Appendix A's source column.
- **d-19** W5: the category files keep a Starting recipe only when it names no house engine (FIRESAW, FIREBLOOM, FIREBASS, FIRETINE, FIREKEYS, FIREWHEEL, BURN, the PIANO model); 35 recipes and variant lines were left out, each category with the one line pointing at the project's recipe file. A recipe whose variants line names a house engine went whole, so some FM variants went with it.
- **d-20** W5: the checks' scope. `preset-name-no-brand` lists only unambiguous machine and brand names (words like spire, serum, vital, jupiter hit real English names: 8 false hits of 9 on the house banks). `preset-not-default-envelope` is written for the house's sparse text patches (`.tabula`), where a value left at its default is not written; a JSON bank with every value written cannot show "left at default" to a pattern. Measurements in evidence/W5/checks-measured.txt.
- **d-21** W5: the gate's limits in `prove-a-bank` (`LIMITS`): chord peak -6 dBFS +/- 1 dB; bank within 1 LU (BS.1770 K-weighted, ungated, on the chord); side at least 30 dB under the mid below 120 Hz; energy below 40 Hz at least 40 dB under the whole; first sound 20 ms; tail as the preset states; velocity v110 over v40 by 3 dB and/or its spectral centre up 5 % (both for pad, piano, keys: never only volume); wheel 127 against 0 differs by at least -20 dB; sync within 2 % of the period at 90, 120 and 140 BPM. The review's 12 dB for velocity was not taken: a pad's measured velocity depth is 0.17 of range, and the law asks for audible colour, not loudness. All in one table, changed in one place.
- **d-22** W6: `claude-ai-skill` (1.5.0: one zip of an older `workorder-writer`, from `prompts/workorder/claude-ai-skill.md`) would be a second copy of the interview. Options: keep both; remove the command; keep the command over the planner's skill. Chosen: its prompt file and test removed, the command kept and writing the planner's `workorder-writer.zip` (`writeClaudeAiZips(dir, ['workorder-writer'])`), so a reader of 1.5.0's README still finds it. Its zip read-back test (Python's zipfile, a planted byte) moved into `test/planner.test.mjs` for all five zips; `zipOf` moved to `lib/zip.mjs`.
- **d-23** W6: the synced `ui-mockup` is the web-app version (renders into `.mdd/design/`, a 9:16 full-page default, an HTML/CSS replication stage). Moved here with what holds kept (the one-question interview, explore then pin, a pin prompt's verbatim strings and count guards, iterate by image, the prompt kept with the picture, the family extended by image) and what breaks the house laws dropped: 16:9 in place of 9:16, `design/reference/` in place of `.mdd/design/`, no HTML stage (the order's Never line). Its approval checks and prompt bands are `analyse-a-mockup.md`'s; its measurements are named as `analyse-reference-look`'s.
- **d-24** W6: the kit had no trigger-word match. Defined in `lib/planner.mjs` (`skillFor`): a sentence goes to the description sharing the most content words with it (plurals folded, a short list of function words left out), at least two; a tie at the top or fewer is a misfire. "work order" is in both `workorder-writer`'s and `start-a-build`'s descriptions (both given by the order); the best match routes "set up the project for my work order" to start-a-build and "write the work order" to workorder-writer. 21 sentences in the test, 25 checked by hand.
- **d-25** W6: the placeholder test reads the planner's skill folders (each SKILL.md and its references), not `planner/README.md`, which is the spec. `handover.md` fills its commands with NAME, TEMPLATE and ORDER inside code fences, so the person gets every command filled in by the skill and no angle bracket is left.
- **d-26** W6: `--zip` writes the five claude.ai skills (the order's "exactly five zips"); the project-layout bodies stay on `--out` and on the printed form. `workorder-writer.zip` carries the three templates as its references (`templates/`), read from `prompts/workorder/templates/` when zipped, never copied into `planner/`.
- **d-27** W6: `planner/start-a-build/handover.md` was rewritten to the kit as it is (it said the template is not a flag and `init --from` did not exist yet): the install block, the machine, the commands with `new --from`, `workorder --template` and `workorder check`, the start, the GitHub path. The nine-line list moved to `workorder-writer/stages.md`. `analyse-a-mockup.md` said "five" checks over six named; now six, and the planner README with it.
- **d-28** W7: the example step is the filter step from `questions.md` section 2, written with none of the words `test/base-neutral.test.mjs` refuses in base (it is "every instance", not "every voice"), since base holds only universal engineering and the order also names the filter step. The draft's Never list was taken (its "name a skill that is not installed" line is new here); its interview part is the planner's. `write-a-workorder` names `run-a-workorder` for the start, not `start-from-a-workorder` (d-2).
