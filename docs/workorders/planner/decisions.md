# planner: decisions

Each choice the run made, so the user can overturn it. The first five were taken in `workorder.md` before the run.

- **d-1** Templates are chosen by `--template`, never by configuration. Options: infer from the configuration; a flag. Chosen: the flag, because a rebuild and a new synth share `synth-creator`.
- **d-2** No `start-from-a-workorder` skill in the planner: the start is `Run docs/workorders/<name>/PROMPT.md`. Options: name the skill in the planner; name the sentence. Chosen: the sentence. Note from the run: base has carried a `start-from-a-workorder` skill since 1.5.0 (written before this order ran). The planner never names it; it stays in base, since removing an installed skill is a change to every project and this order does not name it (easiest to reverse).
- **d-3** No generated index of what every skill proves: `workorder check` is the structural check instead.
- **d-4** The UI is never prototyped in HTML; both synth templates say so in their Never list, with the reason from the research.
- **d-5** `planner/` lives in this repo, not its own, so nothing is copied or pinned.
- **d-6** The release is 1.6.0, not the 1.5.0 `workorder.md` names. research-gaps published 1.5.0 first (npm shows 1.5.0). Given in PROMPT.md.
- **d-7** W0.1: doctor --strict was red on the branch because the kit's own install carried the pre-KWB-130 `agents-held`, whose selftest fails under an unattended run. Options: hand-edit `.claude/hooks`; run the kit's own `update` from this checkout. Chosen: `node bin/claude-packs.mjs update`, the kit's sanctioned path (a fix comes with update); it also brought `lib/audience.mjs`, the brief-guard and shape-law changes and `"chart": []` from 1.5.0.
- **d-8** Evidence lives in `docs/workorders/planner/evidence/W<n>/`, not `build/evidence/` (the public repo leaves `build/evidence/` out). Given in PROMPT.md. Home paths in evidence are masked as `~`.
- **d-9** W2: `workorder <name>` runs the check at its end without doctor, and returns 0. Options: the full check (doctor included) and a failing exit; the order's own lines only. Chosen: the order's lines only, printed as what is left to fill in, because a just-written order is all placeholders and the project may be mid set-up; `workorder check <name>` alone runs doctor too, and the runner calls that.
- **d-10** W2: the runner (`run.sh`) and the prompt call the check before the first session only (no `progress.md` yet). Options: before every session; before the first. Chosen: the first, since a run's own work can turn doctor red for a while (a new rule matching no file yet), and a started run is not stopped by it. `run.sh` exits 5 on a refusal. The command is written as the project runs the kit (`{{kit}}`, filled by `kitCommand`), since `npx --no-install` fails in a project with no node_modules (KWB-76).
- **d-11** W2: a placeholder is `<...>` anywhere outside a code fence, inline code included, and a Done when must hold a digit or a path to a test, as the order states. The rebuild template, kept as its source wrote it (W1.2: two changes only), has 16 of its 19 Done whens refused until filled with counts ("every sheet has its report" names no number). Recorded, not loosened: the house law is a number or a test on every step, and the planner's Stage 8 asks for the same.
- **d-12** W2 findings on `admiral-fleet` (from the history repo; the public repo left it out), checked as written for the kit itself: 13 refusals, recorded as findings about that order and not fixed (it is finished and not in this repo). 7 placeholders are metavariables in inline commands (`<main checkout>`, `<trunk>`, `<scratch>`, `<version>`, `<step>`): a finished order should name them as shell variables or fill them. 6 Done whens hold no digit and no test path (W0.0, W1, W2, W3, W7, W8), several measured in words ("one name removed", "every section has counts"). It has no install block (a warning). Evidence: docs/workorders/planner/evidence/W2/admiral-fleet-check.txt.
- **d-13** W3: the install block is parsed with `yaml` 2.9.1, pinned as the kit's one runtime dependency (row in docs/versions.md). Options: a parser of our own for the subset; a pinned parser. Chosen: the pinned one, as the order allows, because the block holds lists and maps (`looks`, `guards`) and a hand parser would be a second YAML; `yaml` has no dependencies of its own. Only `lib/` (the CLI) imports it; no hook does.
- **d-14** W3: the block's layout keys replace the layout's own values for those keys (the block is the truth for the order), then `update` runs once; `new --config X --from` with a block naming another configuration is refused, naming both; a block with no packs takes its configuration's defaults, as `init --config` does.
- **d-15** W3: the test of `enable` switches on `hooks/user-asks.mjs`, not the handover's example `hooks/idle-wake.mjs`, which crashes when enabled alone (KWB-135, logged open). KWB-136 (every update wrote `"chart": []`, breaking chart-first) was found by the noop test on this branch and fixed here, since the release ships it.
