## 3. Machine-knowledge ledgers

The file holds per-machine ledgers (data, not methods), all under `## 12` of `~/projects/eproms/reverse-engineer.md`: Ensoniq ESQ-1, Mirage; Roland JP-8000, D-50, SDE-330/SRV-330, SRV-2000, DEP-5; Oberheim OB-Xa, OB-8; TC Reverb 4000, 2290, Triple-C, M-ONE; Lexicon PCM 90/91, PCM 80, earlier units, PCM 60, PCM 70, 224, M300, family pass; Access Virus B/C; Eventide H3000, H3500; Yamaha REV7, REV5, SPX90; Sony DPS-D7, DRE-2000; Korg DRV-1000; AMS RMX 16. Plus a modulation-survey ranking (AN1x for rotary, DLS-300) and an open-items list per machine.

The kit holds none of them (checked: no machine address, table offset or ledger of any of these in `packs/`, `prompts/`, `docs/`, `global/`). That is correct: a per-machine ledger is data. It belongs with the machine, outside the kit: in each machine's own repo (`docs/research.md`, `docs/laws.md`, `todo.md`) and the archive/eproms project's `reverse-engineer.md`, with the reference library holding a per-machine "what is known" index. The kit should hold only the PROCESS for keeping one: provenance tags (R-law), withdrawals in place (R-wd), the open-items-with-leads list (`re-deliverables`). A new user of the kit starts every machine from zero, unless the reference library ships such an index; that is a data question, not a kit gap.

One naming/evidence convention the kit lacks (see rows 28 and 113): tags `[EMU]`, `[DS]`, `[REF]`, `[SCH]`-vs-`[DS-REF]` and the tier word (Tier-2) are in the ledger's vocabulary; R-law lists seven tags only.
